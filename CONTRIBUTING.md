# Contributing and repository management

This file is the map for the repository: what Git ignores, how to put the project on GitHub, how changes are checked, and how to report a bug or a feature. The Code of Conduct is [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## What Git ignores

`.gitignore` keeps these out of GitHub:

| Ignored | Why |
| --- | --- |
| `.venv/` | Local Python install. Each person creates their own. |
| `__pycache__/`, `*.pyc` | Generated bytecode. |
| `.env`, `.streamlit/secrets.toml` | Secrets. |
| `downloads/*` except `downloads/.gitkeep` | Videos belong in the user's Downloads folder, not the repo. |
| `*.mp4`, `*.part`, `*.ytdl` | Finished and partial video files. |
| `build/`, `dist/` | PyInstaller output, including `TwitchBatch.exe`. |
| `.DS_Store`, `Thumbs.db`, `desktop.ini` | Operating-system junk. |

`web/index.html`, `server.py`, and `TwitchBatch.spec` stay in Git. They are the app.

## Push this project to GitHub

This folder may not have a Git remote yet. From the project folder:

```powershell
git init
git add .
git status
git commit -m "Add TwitchBatch local downloader"
git branch -M main
```

On GitHub, create an empty repository under [Himanshu-5680](https://github.com/Himanshu-5680). Do not add a generated README there, or the first push will conflict. Then:

```powershell
git remote add origin https://github.com/Himanshu-5680/TwitchBatch.git
git push -u origin main
```

Use the repository name you actually created. Later changes are:

```powershell
git add .
git commit -m "Describe why this change exists"
git push
```

Before every commit, run `git status` and confirm no `.mp4`, `.env`, or `dist\` file is staged.

## GitHub Actions

`.github/workflows/check.yml` runs on every push and pull request. It installs `requirements.txt`, compiles the Python files, and checks that a `.docx` with two Twitch links is read correctly. It does not download a video.

If the check fails, open the Actions tab on GitHub and read the log before merging.

## Report a bug

Use the Bug report template (Issues → New issue → Bug report), or open an issue with:

1. What you did.
2. What you expected.
3. What happened instead, including the status-card text.
4. Windows or phone, and whether you used `python server.py` or `TwitchBatch.exe`.

Do not attach the video file. A short description of the link type is enough (VOD, clip, or live).

## Request a feature

Use the Feature request template. Say who needs it and what should change. One feature per issue.

## Change the code

1. Read the [Code of Conduct](CODE_OF_CONDUCT.md).
2. Fork the repository and create a branch: `git checkout -b short-description`.
3. Run the app locally with `python server.py` and open [http://127.0.0.1:8787](http://127.0.0.1:8787).
4. Open a pull request to `main`. Describe why the change exists and how you checked it.

The page lives in `web/index.html`. The server in `server.py` reads that file. Do not put a second copy of the page in another folder.

## Phone app, the fast way

There is no Android APK in this repository. TwitchBatch downloads with Python, yt-dlp, and FFmpeg on the computer that runs the server. Packing that stack into an on-device APK is not the fast path, and this project does not build one.

The fast way to use a phone:

1. On the PC, run `python server.py --host 0.0.0.0 --port 8787`.
2. On the phone, open `http://<that-pc-ip>:8787` in Chrome.
3. In Chrome, use Add to Home screen. That gives an icon without an APK. Downloads still save on the PC. A finished row has a link if the phone also needs a copy.

An installable APK only makes sense after the site has a public HTTPS address. The fastest wrapper then is [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap), which builds a Trusted Web Activity from that URL. The APK still opens this website. It does not move yt-dlp onto the phone. Build that only when you are ready to host the server, and only from a machine that has the Android SDK.
